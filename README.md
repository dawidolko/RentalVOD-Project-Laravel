# RentalVOD

> 🎬 **Rules the admin can rewrite** — a VOD rental platform where the recommendation engine is an editable expression, not a hard-coded query

**RentalVOD** rents films. A visitor browses the catalogue, a signed-in user fills a basket, checks out and gets a loan with a return date; a premium upgrade unlocks the extended version of a title. Around that sit loyalty points, referral codes, friendships, opinions and recommendations between users.

The part worth reading is the recommendation engine. Instead of a fixed `where rate > 4`, the rule is a **Hoa\Ruler expression held in the cache** — the admin edits it in the settings screen, and the catalogue starts recommending by the new rule without a deploy.

## 🎯 Key Features

- **An editable recommendation rule** — `RecommendationService` evaluates a Hoa\Ruler expression such as `movie["rate"] > 4 and movie["recommendations_count"] > 0` against every film. The admin changes the thresholds in the panel; the rule is stored in the cache, so the change is live immediately.
- **Rentals, not purchases** — checkout creates a `Loan`, and a film can be upgraded to premium for the extended cut. The catalogue and the loan are separate records, which is what makes a return date possible.
- **Loyalty points and referral codes** — both are their own tables against the user, so a discount has a provenance rather than being a number someone typed in.
- **Friends who can recommend** — friend requests are sent, accepted or declined, and a user can recommend a film to a friend; those recommendations feed the counter the rule engine reads.
- **Opinions with ratings** — a film's rating is the average of what users actually left, which is the other half of the recommendation rule.
- **Promotions that can be switched off** — the admin toggles promotions globally and can set a super-promo price on a single film.
- **An admin area for the whole model** — users, orders, films, categories, per-user order history and the settings that drive the rule engine.
- **Findable** — `sitemap.xml` is generated by a controller, so it follows the catalogue.

## 🧩 How the Rule Engine Works

```php
// app/Services/RecommendationService.php
$rule = Cache::get('recommendation_rule', 'movie["rate"] > 4 and movie["recommendations_count"] > 0');

foreach ($movies as $movie) {
    $context = new Context();
    $context['movie'] = $movie->toArray();

    if ($this->ruler->assert($rule, $context)) {
        $recommended[] = $movie;
    }
}
```

The admin screen writes a new expression through `setRule($rate, $recommendationsCount)`; the top five are then sorted by how many recommendations each film received. Swapping the rule never touches a controller.

## 🗄️ The Model

```
User ──< Loan >── Movie ──< Opinion
 │                  │
 │                  └──< PremiumMovie        (the extended cut)
 ├──< LoyaltyPoint
 ├──< ReferralCode
 ├──< Friendship >── User
 └──< Recommendation >── Movie
```

`Role` is a table, so promoting a user to admin is data, not a migration.

## 🚀 Getting Started

### Prerequisites

- PHP 8.2 or newer with Composer
- Node.js 18 or newer with npm
- MySQL 8 (or MariaDB)

### 1. Clone and install

```bash
git clone https://github.com/dawidolko/RentalVOD-Project-Laravel.git
cd RentalVOD-Project-Laravel

composer install
npm install && npm run build

cp .env.example .env
php artisan key:generate
```

### 2. Database

Set the connection in `.env`, then:

```bash
php artisan migrate --seed
```

### 3. Run

```bash
php artisan serve       # http://127.0.0.1:8000
```
